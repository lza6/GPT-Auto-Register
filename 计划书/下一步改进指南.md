## 3. P0/P1 Bug 与技术债详案

### 3.1 T1 — 修复 `api/proxies.py:/health` 冗余赋值

**现状**（`api/proxies.py` diff，第 50-80 行附近）：
```python
async def check_one(line: str) -> dict:
    async with sem:
        proxy_url = proxy_service._http_url(line) if ":" not in line.split(":")[-1] or line.count(":") <= 2 else proxy_service._http_url(line)  # ← 无效三元，两边都调 _http_url
        parts = line.split(":")
        if len(parts) >= 4 and "-" in parts[2]:
            proxy_url = proxy_service._kookeey_url(line)
        else:
            proxy_url = proxy_service._http_url(line)  # ← 立即覆盖上一行
```

**根因**：第一行 `proxy_url` 赋值的三元表达式条件与分支结果都调用 `_http_url(line)`，是残留的调试/未完成代码，第二段 if/else 立即覆盖它。逻辑上等效于只有 if/else，但浪费一次 `_http_url` 调用且让读者困惑。

**修复方案**（删第一行，保留 if/else）：
```python
async def check_one(line: str) -> dict:
    async with sem:
        parts = line.split(":")
        if len(parts) >= 4 and "-" in parts[2]:
            proxy_url = proxy_service._kookeey_url(line)
        else:
            proxy_url = proxy_service._http_url(line)
        try:
            from urllib.parse import urlparse
            u = urlparse(proxy_url or "")
            host, port = u.hostname, u.port
            if not host or not port:
                return {"line": line, "ok": False, "error": "解析失败"}
            try:
                _, _ = await asyncio.wait_for(
                    asyncio.open_connection(host, port), timeout=3)
            except (asyncio.TimeoutError, OSError) as e:
                return {"line": line, "ok": False, "error": f"不可达: {type(e).__name__}"}
            return {"line": line, "ok": True, "error": ""}
        except Exception as e:
            return {"line": line, "ok": False, "error": str(e)[:50]}
```

**验证**：`pytest tests/test_api_extras.py -k proxy`（若无该用例，T1 顺便补一条 mock `_http_url`/`_kookeey_url` 的单测，覆盖 kookeey 与 http 两分支）。

**注意**：TCP 连通性只验证端口可达，不验证代理认证/转发能力。对 kookeey 动态住宅，端口可达后仍可能因账密/国家码错误失效——T3 前端徽章应显示"TCP 可达≠可用"，文档说明边界。**未来 v3.2 可加真实 HTTP 探测**（通过代理请求一个外部 IP 回显服务），见 §6。

### 3.3 T6 — 浏览器池 acquire 占位填充逻辑落地（H3 闭环）

**现状**：`services/browser_pool.py:acquire()` 注释写明"释放锁后再创建（camoufox 启动慢）""先返回占位，创建由调用方在锁外完成"，返回 `inst.camoufox=None, browser=None` 的占位实例。**已 grep 实证：`services/browser_register.py` 对 `browser_pool|get_browser_pool|pool.acquire|pool.release|BrowserPool` 零命中——调用方完全未接入池**，池化路径当前是死代码（max_size=0 时根本不走，max_size>0 时 acquire 占位无人填充）。

**待确认**：
```bash
grep -n "browser_pool\|get_browser_pool\|pool.acquire\|pool.release" services/browser_register.py
```

**若 browser_register 未接入池**（大概率，因为 healthz 的 `browser_pool_size` 默认 0 走按需启停）：

1. 在 `browser_register.py` 注册流程开头：
```python
from services.browser_pool import get_browser_pool
pool = get_browser_pool(self.config)
if pool is not None:
    inst = await pool.acquire(proxy_url)
    if inst is not None:
        if inst.camoufox is None:
            # 锁外填充：启动 camoufox 实例
            inst.camoufox, inst.browser = await self._launch_camoufox(proxy_url)
        try:
            result = await self._register_with_browser_inst(inst, ...)
            return result
        finally:
            await pool.release(inst)
# pool 为 None（max_size=0）走原冷启动路径
return await self._register_cold(proxy_url, ...)
```

2. 提取原冷启动逻辑为 `_launch_camoufox(proxy_url) -> (camoufox, browser)` 与 `_register_with_browser_inst(inst, ...)`，避免重复代码。

**验证**：
- `config.browser_pool_size=2`，并发注册 2 个账号，观察 camoufox 进程数不爆增（复用）
- `pytest tests/test_v3_new_modules.py::TestBrowserPool` 全绿
- shutdown 时 `pool.cleanup()` 关闭实例（已有 shutdown_handler 调用 `browser_register.cleanup()`，需确认 cleanup 委托到 `pool.cleanup()`）

**风险**：池实例绑定 `proxy_url`，但本项目代理是 per-账号 独立（kookeey 每账号独立 IP）——**池化会串 IP**。这正是 `browser_pool.py` 注释里写的权衡。**结论：默认 `browser_pool_size=0` 不池化是正确的**，仅在用户用固定通用 HTTP 代理（非 kookeey 动态）时才开池。T4 的前端输入框必须带这个说明文字。

### 3.7 T4 前置 — settings 字符串存储污染 int 字段（实证 P0 矛盾）

**实证**：`api/settings.py:71` `set_setting(key, req.value)` 把所有值存为字符串（`SettingsUpdateRequest.value: str`），同时 `:76` 同步写 `config.json` 也存字符串。后果：

- `token_refresh_interval_sec` 前端保存 `21600` → config.json 存为 `"21600"`（字符串）
- `main.py` 启动跑 `config_schema.validate_config` → 命中 `int in expected_types and isinstance(value, str)` 分支 → 告警"数字被存为字符串，建议改为 int 类型"
- **T4 自造脏数据，与 §0.1 "堵住脏数据源头"的目标自相矛盾**

**这与 v2.x 已有的 `register_concurrency`/`register_interval_sec` 脏数据是同一根因**——`_as_int`/`_as_bool` 在运行时兜底掩盖了它，但 `config_schema` 会告警。

**修复选项**（两选一，推荐 A）：

- **A（最小改动，推荐）**：`update_setting` 在写入前按 `config_schema._CONFIG_SCHEMA` 做类型转换——int 键 `int(value)`，bool 键转 bool，存 int/bool 而非字符串。这样 config.json 保持正确类型，schema 不告警。
  ```python
  def _coerce_value(key: str, value: str):
      """按 config_schema 把字符串值转为正确类型，减少脏数据。"""
      try:
          from services.config_schema import _CONFIG_SCHEMA
          if key in _CONFIG_SCHEMA:
              expected = _CONFIG_SCHEMA[key][0]  # 期望类型元组
              if int in expected and str(value).strip().lstrip("-").isdigit():
                  return int(value)
              if bool in expected:
                  return str(value).strip().lower() in ("1","true","yes","on")
      except Exception:
          pass
      return value
  ```
  在 `update_setting` 内 `coerced = _coerce_value(key, req.value)` 后 `set_setting(key, str(coerced))` + `config[key] = coerced`。

- **B（根治，改动大）**：把 `SettingsUpdateRequest.value` 从 `str` 改为 `str|int|bool|float`（pydantic Union），前端直接传正确类型。但会破坏前端现有 `value: String(value)` 调用，需同步改 app.js，工作量更大。

**依赖检查**：选项 A 的 `_coerce_value` 调用 `config_schema._CONFIG_SCHEMA`（私有属性，但同仓库内可接受），不引入新依赖。

**⚠️ 实证修正**：已 grep `get_setting(` 调用方——只有 `tests/test_settings.py:41` 断言 `get_setting("register_interval_sec") == "15"`（**字符串比较**）。选项 A 若把值存为 int，此断言会失败（`15 != "15"`）。因此：
- 选 A 时**必须同步改 `test_settings.py:41`** 断言为 `== 15`（int），或改用 `int(get_setting(...)) == 15`。
- 选 B（value 改 Union 类型）同样破坏此断言。
- **无论选 A 或 B，`test_settings.py` 都要跟着改**。这是文档原 §3.7 说的"读取方都不崩"的不准确之处——运行时确实不崩（`_as_int` 兜底），但**测试断言依赖字符串值**，必须同步更新。已在 §7.3 复现坑追加。

**注意**：此 bug 不在 T4 内"顺便修"会留下矛盾——**T4 与 §3.7 必须一起做**，否则前端保存反而制造 schema 告警。已把 T4 升级为依赖 §3.6+§3.7 的复合任务。

### 4.2 T8 — 失败诊断前端卡片化

**现状**：`app.js:122` 仅把 `failure_diagnosis` 文本塞进 `#failureDiagnosis` div。

**增强**：拆解为分类卡片，每类一个徽章 + 占比条：

```javascript
function renderFailureDiagnosis(ft) {
  const box = document.getElementById('failureDiagnosis');
  if (!ft || !Object.keys(ft).length) { box.style.display='none'; return; }
  const total = Object.values(ft).reduce((a,b)=>a+b,0);
  const labels = {risk_control:'⚠️风控',otp_timeout:'⏱️验证码超时',network:'🌐网络',server_5xx:'🔥5xx',unknown:'❓未知'};
  const colors = {risk_control:'red',otp_timeout:'orange',network:'blue',server_5xx:'orange',unknown:'gray'};
  box.style.display='block';
  box.innerHTML = '<b>失败分类</b>（共 '+total+'）' +
    Object.entries(ft).sort((a,b)=>b[1]-a[1]).map(([k,v])=>{
      const pct=(v/total*100).toFixed(0);
      return `<span class="badge ${colors[k]||'gray'}">${labels[k]||k} ${v} (${pct}%)</span>`;
    }).join('');
}
```

`app.css` 加 `.badge.gray{background:#888}` 等缺色。
