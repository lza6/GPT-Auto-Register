190 项测试全绿 覆盖率 69% v2.0.0 Released

一、上下文（Context）

这是已在生产部署的 GPT（OpenAI/ChatGPT）账号批量注册管理系统：Web 控制台 + 协议/浏览器注册引擎 + 邮箱池 + 代理池 + chatgpt2api 对接。v1 时代"能跑"，但存在一批只会在真实生产才暴露的隐患。

本次把 v1 → v2.0，并做了一次终局闭环总审计：三路审计子代理（后端/前端契约/部署）+ 独立复验线程，对全部代码做"最狠反向审判"，发现并修复了大量此前遗漏的伪闭环、竞态、硬编码凭据、契约断裂、O(N²)、体验断裂问题。

二、直觉（Intuition）

核心判断："看起来能用" ≠ "生产可用"。逐条推导出关键风险：

  • 伪安全：`auth_key` 为占位符时默认裸奔 → 一旦部署到公网，refresh_token（长期资产）、账号密码、代理账密全部可读可写。
  • 竞态：两个并发「开始注册」都能通过 `is_running` 检查 → 同一批邮箱重复注册、重复触发 OTP。
  • 凭据泄漏：验证码明文写日志（经 /api/logs 可查）、脚本硬编码 `chatgpt2api` 弱密钥、`_get_chatgpt2api_admin_key` 静默回退弱密钥。
  • 类型脆弱：settings 接口把数字存成字符串，前端清空输入框存 `""` → `int("true")`/`int("")` 直接崩溃，后台任务卡死"运行中"。
  • 契约断裂：FastAPI 0.141 惰性路由下 `/api/logs`（无尾斜杠）404；export-accounts 失败被前端误报成功。
  • 性能：分页 total 全表装载、refresh_all O(N²)、导出串行刷新、前端 3 秒轮询全量日志。

三、做了什么（What Was Done）

🔒 安全加固（CRITICAL 全修）

  • 强制鉴权auth_enforced=true + 占位符密钥 → 服务启动即失败（fail-fast），杜绝假安全
  • 环境注入支持 GPT_REGISTER_AUTH_KEY / GPT_REGISTER_AUTH_ENFORCED 环境变量，零改 config 启用鉴权
  • 凭据治理proxy_chain kookeey 账密从 proxies.txt 解析；全部脚本 + API 移除硬编码 chatgpt2api 弱密钥
  • 日志脱敏验证码不再明文写日志（4 处）
  • 清空保护confirm='clear' 服务端确认 + 自动备份到 data/backups/（保留 7 份）
  • 白名单settings 接口只允许白名单键，禁止覆盖 auth_key

⚡ 可靠性 / 性能

  • 并发register_concurrency 落地：asyncio.Semaphore + gather，原子 try_start 防并发启动竞态
  • 防御解析_as_int：配置被写坏为 "true"/"" 时回退默认，不再崩溃（全链路 4 个引擎）
  • 异常兜底register_one 抛异常也计失败入库（不再静默丢邮箱）；先落库成功再标 used
  • 分页 COUNTtotal 用 COUNT(*) 替代全表装载（accounts/emails）
  • 连接收敛全部 API 改用 db_session()，异常不泄漏连接
  • 验证码窗口otp_min_age_window_sec 等可配置；graph seen_codes 生效、ISO 时间转 epoch 比较

🎨 前端 / 契约

  • 搜索/分页注册记录、邮箱池支持邮箱搜索（300ms 防抖）、状态筛选、分页
  • 主题深色/浅色一键切换（跟随系统）+ 移动端适配
  • 日志降载增量 after_id 拉取 + 页面隐藏暂停 + 全量 DESC 反转保证顺序一致
  • 防重复导入/手动添加弹窗按钮 loading 禁用；export-accounts 失败不再误报成功
  • 契约修复 /api/logs 无斜杠 404（FastAPI 0.141 惰性路由）

📦 部署 / 代码质量 / 测试

  • 依赖requirements.txt 唯一依赖清单；脚本 playwright 缺失引导
  • 脚本refresh_all init_db 防首次报错、端口统一 23456、停止.bat 端口精确匹配
  • 架构资产Spec-Kit 治理宪法 + docs/ADR/ ADR-001~003 + workflow_status.md
  • 测试67 → 190 项用例；覆盖率 48% → 69%（核心 register_engine 85%）
