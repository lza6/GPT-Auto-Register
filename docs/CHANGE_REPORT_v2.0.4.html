二、直觉（Intuition）

核心判断："我的复现方法失败 ≠ 用户没遇到 bug"。逐条推导：

  • 第一直觉错的：看到系统 cmd chcp 显示 65001，断定"UTF-8 中文 bat 没问题"。但 subprocess.Popen 启的 cmd 是纯净默认代码页（936），双击用的 cmd 也是默认——65001 是某个 profile 改的，不代表真实双击环境。
  • 复现方法系统性踩坑：subprocess.Popen(["cmd","/c",bat]) 在中文路径下 cwd 传递乱码；cmd /c "带空格路径" 被 shell 切词；Git Bash→cmd 的 cwd 中文传递系统性破坏。最终用 os.startfile（ShellExecuteW）才真实复现双击。
  • 根因双重：① UTF-8 无 BOM 含中文 → cmd 按 GBK 读取中文字节错位 → cd /d "%~dp0" 失败 → rc=255；② GNU timeout.exe 劫持 PATH → timeout /t N 报 invalid time interval '/t'。
  • 修复必须字节级：只把中文译英文不够，必须验证非 ASCII 字节数=0；只修 timeout 不够，chcp 也要绝对路径免疫。

三、做了什么（What Was Done）

🛡️ 双击闪退根因修复（CRITICAL）

  • 纯 ASCII启动.bat/停止.bat 全文转纯 ASCII（中文 rem/echo 译英文），任何代码页下字节一致，免疫 GBK 错位
  • timeout → pingtimeout /t N /nobreak >nul → ping -n N+1 127.0.0.1 >nul（3 处），免疫 GNU coreutils timeout.exe 劫持
  • chcp 绝对路径chcp 65001 → %SystemRoot%\System32\chcp.com 65001，免疫 PATH 劫持
