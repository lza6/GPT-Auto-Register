5. 变更测验

以下测验必须通过，确认你理解本次变更：

Q1: settings 写入时，DB settings 表和 config.json 分别存什么类型？为什么这么设计？
DB 存原始字符串（get_setting() 返回 str 的契约被 test_settings 依赖），config.json 存 _coerce_value 按 schema 转的正确类型。脏数据危害只在 config.json（schema 告警），DB 字符串 KV 无害且运行时 _as_int/_as_bool 兜底。
Q2: 浏览器池化为什么不会串 IP？默认 browser_pool_size 是多少，为什么？
代理在 browser.new_context(proxy=...) 按 context 设置，camoufox browser 实例本身代理无关；池化复用 browser + 每账号新建 context，各 context 携带各自代理。默认 browser_pool_size=0 不池化——kookeey 动态代理每账号本就独立 IP，池化收益主要在固定通用 HTTP 代理场景。
Q3: register_one 池化路径中，异常发生时实例如何处理？为什么不能直接 release 复用？
pooled_ok=False（未正常完成到 context.close()）时先 browser.close()+camoufox.stop()，再把 inst.camoufox/browser 置 None 标记为占位，让 release 走占位丢弃分支。直接复用可能损坏的实例会让后续账号反复失败，放大故障。
Q4: token 巡检默认开启还是关闭？为什么？巡检失败会删旧 token 吗？
默认关闭（token_refresh_enabled=false），避免与 chatgpt2api 自动刷新职责冲突导致 OpenAI 限流/吊销 refresh_token。失败仅记 log + 跳过，不删旧 token（保留可用旧值）。
Q5: 前端拆分后用哪三重校验防"漏迁 id/class"静默失效？
① node --check app.js 语法；② getElementById 引用的 id 与 index.html/弹窗注入 id 双向比对；③ 真实无头浏览器点遍标签页 + 弹窗，断言 0 console error + 0 request failed。
Q6: /api/proxies/health 探测的是什么？能代表"代理账号可用"吗？
仅探测 TCP 端口可达（3s 超时），不能代表账号可用——kookeey 动态住宅端口可达后仍可能因账密/国家码错误失效。真实 HTTP 出口探测是 v3.2 前瞻。
Q7: T4b 把 int 字段存成 int 后，为什么 test_settings.py:41 的 get_setting(...) == "15" 字符串断言仍然通过？
因为 set_setting 写入 DB 的仍是原始字符串 "15"（只有 config.json 存 int），get_setting 从 DB 读取返回 "15"，字符串契约未被破坏。
