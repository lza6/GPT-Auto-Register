# ADR-005: v2.1 终局闭环审计 — 注册链路加固 + OTP/常量收敛 + 资源安全

**状态**：已采纳（2026-08-06）
**关联**：`scripts/verify_account_login.py`、`scripts/refresh_all.py`、`services/browser_register.py`、`services/otp_extractor.py`、`services/constants.py`
**本次提交**：v2.1 终局审计

## 背景

v2.0.4 后用户报告 `refresh_all.py` 批量刷新大量账号 `180s 超时强杀`。代码考古发现真实根因不是诊断里写的 `input[name=email] 15s 超时`（那是 `verify_microsoft_login.py:59`，不是失败链路），而是 `verify_account_login.py.run()` 是**孤儿旧代码**：没复用 `browser_register.py` 已有的 `detect_login_page`/`_resolve_cf` 形态分流，遇到 CF 挑战页或 OpenAI 改版页就裸等密码框 + 裸等 OAuth code，最坏撞 `refresh_all.py` 的 180s 强杀。

同时发现 4 个自造漏洞：
1. `verify` 截图落 `data/debug/` 但目录不存在时 `try/except: pass` 静默吞错（违宪）。
2. `verify` 返回码 3/4 但 `refresh_all.py` 仍记 `exit=1`、reason 空——前后端契约断。
3. `browser_register` CF 重试换代理时 `new_context` 抛异常会让 `page` 悬空、后续 `context.close()` 二次抛——真实 camoufox 可能资源泄漏。
4. `_writeback_token` 返回 False 时 verify 仍报 `EXIT_SUCCESS`——token 没回写却报成功，数据静默丢失。

另发现 DRY 反模式：OTP 提取正则三份完全相同（email/graph/imap service），OAuth client_id 6 处硬编码。

## 决策

### 1. verify 复用形态分流，明确退出码语义
- goto 后用 `detect_login_page` 形态分流：CF/unknown/callback/email/otp/about-you/password。
- 退出码常量化：`EXIT_SUCCESS=0` / `EXIT_FAIL=1` / `EXIT_NEED_2FA=2` / `EXIT_CF_BLOCKED=3` / `EXIT_UNKNOWN_PAGE=4`。
- CF 页调 `_resolve_cf`，解不开早退码 3；unknown 页早退码 4 + 截图 + 页面摘要；callback 页直接换 token；email/otp/about-you 明确早退码 1（本脚本是密码登录流程）。
- 截图目录 `data/debug/` 用 `mkdir(parents=True, exist_ok=True)` 自动创建，不再静默吞。
- `_writeback_token` 返回 False 时返回 `EXIT_FAIL`，token 丢失不再静默。

### 2. refresh_all 适配新退出码
- `EXIT_NAMES` 映射表：rc→(is_ok, reason)。rc=3→reason=cf_blocked，rc=4→reason=unknown_page。结果文件可区分失败类型。

### 3. browser_register CF 重试资源安全
- `_cf_retry_max` 配置项（默认 2）。CF 解不开时关当前 context → 取新代理 → 开新 context → 重新 goto。
- `new_context`/`new_page` 包在 try/except 内，失败则 break 到 `cf_blocked`，避免 page 悬空。
- 全部失败才返回 `cf_blocked`，不再裸超时。

### 4. OTP 提取三合一（B3）
- 新建 `services/otp_extractor.py`：`extract_otp_code(body)` + `is_otp_mail(subject, from)`。
- 三个 email service 的 `extract_otp_code`/`_extract_otp` 改为单行委托，行为完全一致（font-24px > bg-F3F3F3 > max(6位数字)，排除全同数字 + 地址黑名单 90210 等）。

### 5. 常量集中（B5）
- 新建 `services/constants.py`：`OAUTH_CLIENT_ID`/`OAUTH_REDIRECT_URI`/`OAUTH_AUDIENCE`/`OAUTH_AUTH0_CLIENT` 等。
- `browser_register.py` 内联常量改为从 constants import，保留模块级别名供旧 import 向后兼容。
- `revive_import.py`/`protocol_register.py` 等长尾项后续会话迁移（不阻塞本次）。

## 后果

**正面**：
- verify 链路不再 180s 裸超时，CF/unknown 明确早退 + 可追溯。
- 真实 camoufox 资源泄漏风险消除。
- OTP 正则改一处生效三处，OAuth 常量改一处生效六处。
- 测试 207 项全绿（+13 OTP 提取 + 4 verify/CF 分支）。

**负面/边界**：
- verify 修复仅 mock 验证（无真实账号可跑），真实 CF Turnstile 点不掉时仍需人工或换代理——但已明确标记 `cf_blocked` 不再卡死。
- `revive_import.py`/`protocol_register.py` 常量迁移为长尾，本次只收敛 `browser_register`，未消除全部 6 处硬编码（已记录到 tasks 长尾）。
