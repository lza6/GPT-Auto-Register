# ADR-001: 协议优先、浏览器兜底的注册引擎

**状态**：已采纳（2026-08-05）
**关联**：`services/protocol_register.py`、`services/browser_register.py`、`services/register_engine.py`

## 背景

早期注册走纯浏览器自动化（camoufox），每个账号启动一个浏览器实例，慢、吃内存、依赖页面选择器稳定性。抓包确认 OpenAI 注册链路可纯协议完成（curl_cffi + Sentinel PoW），但 create_account 等步骤需要真实前端 sentinel 参数。

## 决策

注册引擎采用**协议优先、浏览器兜底**策略：
1. 默认 `protocol_first=true`：先走 `protocol_register`（curl_cffi + sentinel，无浏览器）。
2. 协议返回 `fallback_browser=true`（网络错误 / 服务器 5xx / 验证码超时）时，降级 `browser_register`（camoufox）兜底。
3. **风控类失败不降级**（`account_deactivated` / `registration_disallowed` / 验证码限流）：浏览器同样会被拒，降级只会无谓重试触发限流。

失败通过 `_classify_failure` 结构化分类：`risk_control / otp_timeout / network / server_5xx / unknown`。

## 后果

- 正面：批量注册快（纯协议）、省资源、失败可自动兜底浏览器。
- 正面：失败原因可量化统计（`failure_types`）。
- 负面：协议链路对 OpenAI 变更敏感，需维护 sentinel flow 常量。
- 负面：浏览器兜底路径仍需选择器（已收敛到 `browser_selectors.py`）。

## 替代方案

- **纯浏览器**：可靠但慢、重、成本高 —— 否。
- **纯协议**：快但不处理 CF / 复杂页面 —— 否，保留兜底。
- **第三方注册服务**：依赖外部，数据安全不可控 —— 否。

## 验证

- 单元测试：协议成功不触发浏览器；网络失败降级；风控不降级；`use_browser=false` 不降级。
- 覆盖率：protocol_register 69%、register_engine 89%、browser_selectors 100%。
