# ADR-003: 安全基线 — 强制鉴权 / 白名单 / 清空备份

**状态**：已采纳（2026-08-05）
**关联**：`api/__init__.py`、`api/settings.py`、`api/register.py`、`services/proxy_chain.py`、`scripts/*chatgpt2api*.py`

## 背景

v1 时代存在多处安全缺口：占位符 `auth_key` 导致 `/api/*` 默认裸奔、`proxy_chain.py` 硬编码 kookeey 账密、settings 接口可写任意 key 覆盖 `auth_key`、chatgpt2api 脚本硬编码弱密钥、清空接口无服务端确认。

## 决策

1. **强制鉴权**：`config.auth_enforced=true` 且 `auth_key` 为占位符/空时，`create_app` 启动即 `RuntimeError`（fail-fast），杜绝"看似有鉴权实际裸奔"。默认 `false` 保持老部署兼容。
2. **代理凭据去硬编码**：`proxy_chain.load_kookeey_credentials()` 从 `proxies.txt` 第一条 kookeey 行解析账密；可用 `--kookeey-user/--kookeey-pass` 覆盖。源码无明文。
3. **设置白名单**：`ALLOWED_SETTINGS_KEYS` 白名单，白名单外（尤其 `auth_key`）一律 400。
4. **chatgpt2api 密钥环境化**：脚本读 `CHATGPT2API_ADMIN_KEY` → `config.json.chatgpt2api_admin_key`；缺失时拒绝运行并提示。
5. **清空备份**：`/api/register/clear` 需 `confirm='clear'` 服务端校验；清空前自动备份 `accounts/emails/tasks` 到 `data/backups/backup_*.json`（保留 7 份）。

## 后果

- 正面：生产默认可关闭裸奔风险；敏感凭据不再随源码泄露；误清可恢复。
- 负面：`auth_enforced=true` 要求部署者先配好真实密钥，否则服务拒绝启动（有意为之）。
- 负面：scripts 现需显式配置 chatgpt2api 密钥（环境变量或 config），否则脚本退出。

## 替代方案

- 反向代理层鉴权（Nginx Basic Auth）：额外组件、未覆盖脚本直连 —— 弃，选择应用内鉴权。
- 密钥管理系统（Vault/Secrets Manager）：对单人项目过重 —— 记为 P3 增强。

## 验证

- 单测：auth_enforced 占位符 fail-fast / 真实密钥严格鉴权；白名单拒绝/放行；清空 confirm+备份+轮转；proxy_chain 凭据解析；脚本缺 key 拒绝。
